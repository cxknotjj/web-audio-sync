# 🎬 音画不同步调节器

**🌐 简体中文** · [English](README.en.md)

**不换播放器、不碰进度条、只把送到扬声器的声音推迟一点。**

浏览器扩展。给**当前标签页的声音**加一段可调的延迟，用来修音画不同步。调多少、什么时候停，都在页面右下角那块面板里完成。

## 🎧 什么时候用得上

声音比画面晚一点，看着就别扭。常见来源：

| 场景 | 典型延迟 |
| --- | --- |
| 蓝牙耳机 / 蓝牙音箱 | 100～300 ms |
| 投屏到电视、投影仪 | 几十～几百 ms |
| 外接声卡、DSP、功放 | 看设备 |
| 播放器自身的音画不同步 | 不定 |

对着口型把数字调大，调到对上为止。

## 📦 安装

**🛍️ 方式一：应用商店（最省事）**

[Edge 加载项商店](https://microsoftedge.microsoft.com/addons/detail/dppjkonmajnmkgepepheieignphmbkfe) · 需要 Chromium 内核 **116 以上**

商店里是**上架版**，比完整版少了链路②。遇到原生 HLS 站点会走链路③，功能一样，只是那条流会多下载一份。

**🧩 方式二：从源码加载（完整版 / 想改代码）**

1. 下载本仓库（`git clone` 或下载 zip 解压）
2. 打开 `edge://extensions`（Chrome 用 `chrome://extensions`）
3. 打开右上角**开发者模式**
4. 点**加载已解压的扩展程序**，选中仓库目录
5. 把扩展图标固定到工具栏

完整版的 zip 在 [Releases](https://github.com/cxknotjj/web-av-sync/releases) 页面。

两个版本只差链路②，详见 [USAGE.md 的构建版本对照](USAGE.md#7-两个构建版本)。**不要同时装在同一个浏览器里**，扩展 ID 不同，会被当成两个扩展。

## 💡 我为什么做它

上网课的时候，老师嘴型总比声音早半拍。换播放器、调进度条、重装驱动，全都没用——延迟发生在声音离开电脑之前的最后一步。

既然问题出在"送到扬声器"这一段，那就只改这一段。于是有了这个扩展：不动播放器，不改网页，只接管当前标签页的声音，推迟几十到几百毫秒。

如果它帮你把口型对上了，文末有件小事想拜托你。

## 🚀 怎么用

不用懂任何技术名词：**打开视频 → 点图标 → 拖滑块**，三步。

![面板说明](store/screenshot-2-panel.png)

1. 打开视频页面，**让它先播起来** —— 标签页没在出声时无法接管
2. **点一下工具栏图标**（或按快捷键 `Alt+Shift+D`），声音交给扩展，页面右下角出现面板
3. 拖动滑块或滚动滚轮，直到口型和声音对上

停止：再点一次图标（或再按一次快捷键），声音立刻回到页面。面板可以拖到任意位置；点 `−` 收起成一条，点 `×` 停止并关闭。

快捷键可以在浏览器的扩展管理页（`edge://extensions/shortcuts`）里改。全屏看片时不用退出来找图标。

### 🔍 面板上都是什么

| 元素 | 作用 |
| --- | --- |
| 大数字 | 当前延迟，单位秒。负号表示声音提前 |
| 滑块 | 拖动调节，范围 −10 秒 ~ +10 秒 |
| `−1s` `−100` `归零` `+100` `+1s` | 快捷档位 |
| 电平条 | 有声音就在动，没声音就不动。**判断有没有出声只看它**，不要看页面自己的音量条 |
| 提示文字 | 当前模式，以及这一页能不能用双向。双向模式下还会多一条链路指示 |
| 停止 | 结束接管，声音回到页面 |

### 🎛️ 三种调节方式

- **拖动滑块**：鼠标按住拖
- **滚轮**：鼠标停在面板上滚动，一格 100 ms，按住 `Shift` 一格 1 秒。向上滚 = 数值变大（声音更晚）。只作用于面板，不会带着页面滚
- **键盘**：鼠标悬停在面板上时，`←` `→` 每次 100 ms，`Shift + ←/→` 每次 1 秒，`Home` 归零。只在悬停时生效，不会和播放器自己的方向键打架

## ⏪ 进阶：让声音提前（双向模式）

<details>
<summary><b>展开：双向模式怎么开、代价是什么</b></summary>

默认只能让声音**更晚**。扩展抓的是浏览器已经渲染出来的音频，里面没有"未来"的声音，物理上没法往前推。

双向模式换了个思路：去拿**页面自己已经下载但还没播到**的那段音频，把它提前放。所以它需要视频是"边下边播"的流媒体，而不是已经完整下载好的文件。

- **开启**：先播放 → 点图标接管 → 面板上点「启用双向」，页面自动刷新一次、回来就已在双向模式（刷新是为了把增强脚本装进去，不用再点第二次）
- **链路**：① 复用页面切片（零流量）/ ② 抓取已下载切片（零流量，仅完整版）/ ③ 重新拉一路（约双倍流量）
- **缓冲**：所有站点的播放器缓冲目标都会从 30 秒放宽到 90 秒 —— 「可安全提前」的余量跟着变大，拖完进度条也不容易卡在边缘（多占几十兆内存，不额外耗流量）
- **缓冲跟不上、拖进度条、广告插播、全屏、退出**：每种情况的实际表现、自动降档与降级规则，都整理在 [USAGE.md 的双向模式一节](USAGE.md#3-双向模式)

> 完整版与商店版的唯一差别就是链路②。它需要 `debugger` 权限，安装警告是「访问网页调试后端」和「读取并更改所有网站上的所有数据」，太重了，不适合放进商店。

</details>

## ❓ 常见问题

<details>
<summary><b>展开：15 个常见问题</b></summary>

**点了图标，什么也没发生**

先确认视频**正在出声**。静音、暂停、或者音量拉到 0 的标签页无法接管，这时页面顶部会弹一条红色提示说明原因。

**接管了，页面音量条正常但没有声音**

这是正常的，不是 bug。浏览器在接管期间会强制静音标签页，声音改由扩展输出。看面板里的电平条——它在动就说明声音在走。如果不动，点一下页面再试。

**面板没出现**

少数页面不允许注入脚本（浏览器内部页、扩展商店、PDF 阅读器）。这类页面上音频本来也捕获不了，图标会短暂显示红色 `!` 角标。

**页面上出现了两个面板**

已修复，1.0.1 起的构建都带这个修复。播放器嵌在 iframe 里的站点（大部分影视站都是），早期开发版本每个框架各画一个。现在只会在真正有播放器的那一层出现。如果还遇到，把网址发我。

**数值调了但听不出变化**

- 确认视频在播，且面板电平条在动
- 延迟很小（几十毫秒）时确实不明显，试试 ±1000 ms
- 如果拖动时数字在变、但声音完全没动，可能是接管已经断了——点停止再重新接管

**面板显示「此页不支持双向」**

这个页面里没找到视频元素。可能是页面还在加载、播放器在别的框架里、或者内容没加载出来。等页面完全加载、视频开始播放后再看。

**面板显示「启用双向」，点了以后页面刷新了**

这是正常的：增强脚本必须在页面加载前注册，所以点下去会补注册并刷新一次。刷新回来后会自动进双向，不用再点。

如果刷新后还是停在「启用双向」，说明这次注册没成功（扩展被浏览器回收、或站点访问权限被手动关掉了）。先确认扩展管理页里这个扩展的「网站访问权限」没被改成「点击时」，再点一次。

**双向模式下拖完进度条，声音对不上**

1.0.1 起的构建里已经修好：进度条一动，扩展就把音频挪到新位置，并清掉被跳过那段缓冲。如果用的是旧版本，重新加载扩展即可。

**双向模式下流量翻倍了**

说明走的是 ③「重新拉一路」。这是页面没有可复用切片时的兜底方案。指示条悬停可以看到具体原因：要么这个站播的是 mp4 直链，要么抓切片失败自动降级了。

**只能提前两三秒，再多就卡**

这是缓冲限制。能提前的量等于"已经下载到多远"。想提前更多，让视频多缓冲一会儿。

**双向模式下画面卡住不动，面板显示「等缓冲 · 还差 N 秒」**

不是卡死了，是扩展在按住画面等切片下载（只有链路① 和 ③ 会按住画面）。数字在变小就是正常等待；一直不变说明这个站喂不动，几秒后扩展会自动把提前量降下来并恢复播放。

**面板显示「音频重新加载中，画面继续」，一直没声音**

这是链路② 的正常中间状态：拖完进度条后，声音要在后台重新缓存，画面不等它。一般几秒内自己接回；超过 8 秒还接不上，扩展会自动降级到链路③（多一倍流量）。频繁出现说明这个站切片给得慢，扩展会自动处理。

**点了归零，声音还是比画面晚一点**

1.0.1 已修复链路② 的零延迟偏移（实测约 1.6 秒）。如果还遇到，先看面板右侧状态：显示「音频重新加载中」就等它接回；显示「可安全提前」但听着仍偏，点停止再重新接管一次。

**声音有轻微咔哒声**

拖动滑块时延迟值在 60 ms 内平滑过渡。特别频繁地大幅拖动时偶尔会有一点跳音，这是音频处理节点的固有特性，无法完全消除。

**换标签页 / 切全屏**

换标签页会先停掉上一个接管。全屏下面板会跟着进全屏，位置保持不变。

</details>

## ⚠️ 已知限制

<details>
<summary><b>展开：它做不到哪些事</b></summary>

| 限制 | 说明 |
| --- | --- |
| 只能在 Chromium 内核上用 | Firefox 没有 `tabCapture` |
| 默认只能延后 | 要提前得开双向模式，且只对流媒体页面有效 |
| 捕获整个标签页 | 页面里的提示音、广告声会一起被延迟。只处理视频音轨做不到 |
| 一次只能接管一个标签页 | 浏览器限制 |
| 接管期间原播放器静音 | 预期行为，声音由扩展输出 |
| 浏览器内部页不支持 | 设置页、扩展商店、PDF 阅读器 |

</details>

## 🛠️ 想改代码 / 想搞清楚它怎么实现的

<details>
<summary><b>展开：文件分工与开发文档</b></summary>

实现原理、三条取数链路的完整对照、实测数据、开发环境搭建、调试方法都在 [`DEVELOPMENT.md`](DEVELOPMENT.md)。

双向模式拆成五个模块，注入顺序就是依赖顺序：

| 文件 | 职责 |
| --- | --- |
| `ads-enh-core.js` | 共享状态与常量、缓冲几何、音频对齐、链路选择 |
| `ads-enh-panel.js` | 面板文案：链路指示、可安全提前、状态发布 |
| `ads-enh-route.js` | 三条链路的实现：复用 MSE / 抓切片 / 再拉一路 |
| `ads-enh-sync.js` | 同步循环：250 ms 一拍的对齐、等缓冲、拖进度条 |
| `ads-enhance.js` | 生命周期：进入 / 退出双向、失败降级 |

界面文案有中英两套，跟着浏览器的界面语言走。要加第三种语言，见 [`DEVELOPMENT.md`](DEVELOPMENT.md) 的「界面文案」一节。

</details>

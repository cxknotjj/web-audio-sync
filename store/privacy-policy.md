# 隐私政策

**音画不同步调节器**（以下简称"本扩展"）

最后更新：2026-11-14

---

## 一句话版本

本扩展**不收集、不上传、不存储任何用户数据**。所有音频处理都在你自己的电脑上、在你的浏览器里完成，不经过任何服务器。

---

## 详细说明

### 本扩展做什么

本扩展把**当前标签页**已经渲染出来的音频，通过浏览器的 Web Audio `DelayNode` 延迟一小段时间后重新输出，用于修正视频音画不同步（例如蓝牙耳机、投屏、录屏场景下的口型错位）。

它**不读取网页内容**（文本、图片、表单、链接都不碰），不修改页面，不下载、不录制、不保存任何音视频。注入的脚本只读取播放器的时间属性，以及页面有没有加载 hls.js 这个库。

### 处理了哪些数据

| 数据 | 是否处理 | 说明 |
|---|---|---|
| 标签页音频流 | 是 | 仅在用户点击扩展图标、主动接管该标签页后建立，用户再次点击图标或关闭标签页时立即销毁。音频样本仅在内存中的 `DelayNode` 里停留最多 10.5 秒，随后输出到扬声器，**不落盘、不编码、不传输**。 |
| 音频电平（RMS） | 是 | 每 150 毫秒算一次响度，只用于驱动界面上的电平条动画。数值仅存在于内存，不存储、不发送。 |
| 延迟设置 | 是 | 你拖动的延迟值（0–10000 毫秒）保存在浏览器本地存储 `chrome.storage` 中，仅用于下次打开面板时恢复上次的数值。**不离开你的设备。** |
| 启用过双向模式的站点（可选功能） | 是 | 只有你在面板上主动点「启用双向」后，**那一个站点**的 origin（如 `https://example.com`）才会记入本地存储 `enhancedOrigins`，用于下次自动恢复这条可选链路。不含页面地址、标题、访问时间。不使用双向模式时该记录为空。**不离开你的设备。** |
| 当前标签页 ID | 是 | 进程内使用，用于把音频流和标签页对应起来。关闭后清除。 |
| 网页文本 / 图片 / 表单 / 链接 | **否** | 不读取。注入的脚本只读取 `<video>` 元素的时间属性（当前播放位置、已缓冲范围、音频来源地址），以及页面是否加载了 hls.js 这个播放器库。 |
| URL 路径 / 查询参数 / 页面标题 | **否** | 不读取。只读取当前页面的 origin（协议 + 域名 + 端口），用于判断该站点是否已启用可选功能。 |
| 浏览历史 | **否** | 本扩展没有申请 `tabs`、`history`、`webNavigation` 等权限，技术上无法读取。 |
| 账号 / 邮箱 / 位置 / 设备标识 | **否** | 不申请，不生成，不采集。 |

### 权限用途

本扩展共申请 5 项 API 权限 + 1 项站点访问权限：

- **`tabCapture`** — 获取当前标签页的音频流。这是本扩展的核心能力，没有它无法工作。
- **`offscreen`** — 在隐藏文档中运行 Web Audio。MV3 的 service worker 不能直接用 Web Audio，必须借助 offscreen 文档。
- **`storage`** — 记住你上次设置的延迟值，以及你启用过双向模式的站点。
- **`activeTab`** — 只在你主动点击扩展图标时，才获得当前标签页的临时访问权。不常驻，不跨标签页。
- **`scripting`** — 在**你点击图标接管的那一个标签页**里注入调节面板和双向模式脚本。注入失败不影响音频功能。
- **`host_permissions: ["*://*/*"]`** — 站点访问权限。安装时授予。用途只有下面两处：

  **一、放宽播放器的缓冲目标。** 每个页面加载时会注入一段 2.6 KB 的脚本（`inject-buffer.js`）。它只做一件事：如果页面用 hls.js 播放，把「最多缓冲多少秒」这个配置从默认 30 秒调大。它不读取页面内容、不修改 DOM、不转发任何数据，判断依据只有页面是否加载了 hls.js 这一个布尔值。

  **二、按站点注册双向模式的增强脚本。** 增强脚本**不对所有站点生效**：只有你在面板上点过「启用双向」的站点，才会被注册进 Chrome 的脚本注册表（`chrome.scripting.registerContentScripts`），记录存在本地 `enhancedOrigins`。没有启用过的站点，增强脚本根本不会被注入，也就不会复制任何音频片段。

  为什么不在安装后按站点申请：增强脚本必须在页面脚本之前（`document_start`）注入才截得到第一个音频片段，而 Chromium 不支持「点击之后补一次 document_start 注入」——用可选权限的话，用户点启用后必须刷新一次页面才生效，每换一个站点都要重新授权 + 刷新。改为安装时授予，代价是安装时多一条站点访问提示；实际作用范围仍由上面的按站点注册限制。你可以随时在浏览器扩展管理页把这个扩展的站点访问改成「点击时」，音频延迟功能不受影响。

### 网络请求

**零。** 本扩展不发起任何网络请求，不加载任何远程脚本、字体、图片或统计代码。所有代码和图标都打包在扩展内部，可离线使用。

因此本扩展也不涉及"远程代码执行"（remote code），符合 MV3 的 CSP 要求。

### 第三方共享

**没有。** 不与任何第三方共享数据，因为根本不采集数据。

### 儿童隐私

本扩展不面向 13 岁以下儿童，也不收集任何年龄信息或个人信息。

### 政策变更

若未来版本的功能变更导致数据处理方式变化（例如新增功能需要网络请求），本页面会先行更新并标注新的"最后更新"日期。

## 技术附录：音频数据流的完整路径

供需要审计的用户和审核人员参考：

```
标签页最终混音
   ↓ chrome.tabCapture.getMediaStreamId()   ← 用户点击图标时才授权
MediaStream（仅音频，video:false）
   ↓ getUserMedia({ audio: { mandatory: { chromeMediaSource: 'tab', ... } } })
MediaStreamAudioSourceNode
   ↓
DelayNode（delayTime ≤ 10.5s）→ AudioContext.destination → 扬声器
   ↓
AnalyserNode（只读电平，不采样、不记录）
```

音频全程在浏览器的音频线程中流转，不进入任何网络栈，不写入任何文件。

捕获期间标签页自身会静音（浏览器强制行为），所以这条链路是用户唯一的出声通道——这也意味着**扩展一旦停止，声音立即回到页面本身**，不会残留任何后台进程。
